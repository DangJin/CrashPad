# CrashPad

用拖拽代替手绘，快速描述车辆碰撞、转弯、变道和匝道汇入现场。

CrashPad 是基于 React + Vite 的事故示意图工作台。打开即进入画布：左侧选择道路模板和场景对象，中间绘制现场，右侧统一调整所选对象的属性。支持过程演示，以及适配小红书、抖音比例的图片和 GIF 导出。

## 功能

| 模块 | 支持内容 |
| --- | --- |
| 道路 | 直路、十字路口、丁字路口、停车区域、匝道汇入 / 汇出、车道增加 / 减少 |
| 道路属性 | 1–6 车道，进入 / 离开段车道数，匝道侧，行驶方向 |
| 车辆 | 双车位置、−180°～180° 朝向、来车方向、直行、转弯、变道、汇入和静止 |
| 路线 | 拖动起点、计划终点和曲线控制点；变道采用 S 形曲线，汇入可对齐主路方向 |
| 红绿灯 | 路口各来车侧独立设置灯色、显示开关和标识朝向，画布点选后在右侧编辑 |
| 事故标注 | 碰撞点，可视化点选车头、车尾、左侧或右侧受损，以及现场说明、地点和时间 |
| 演示 | 已行驶路线、后续动作、完整演示；暂停、进度拖动、重播和 0.5× / 1× / 2× 速度 |
| 导出 | PNG、JPG、循环 GIF，比例选择、实时预览和清晰度设置 |
| 编辑体验 | 可编辑标题、自动保存、撤销 / 重做、重置、网格、缩放及移动端布局 |

## 快速开始

需要 Node.js 20.19+ 或 22.12+，以及 npm。

```sh
npm ci
npm run dev
```

打开 <http://127.0.0.1:5173>。在启动终端按 `Ctrl+C` 停止服务。

开发和构建预览均固定使用 `5173` 端口，并启用严格端口模式。已有本项目的开发服务时直接复用；端口被占用时先检查占用者，不自动改用其他端口：

```sh
lsof -nP -iTCP:5173 -sTCP:LISTEN
```

## 绘制现场

1. **选择道路**：从左侧模板选择最接近现场的路型，在右侧设置车道和方向。
2. **摆放车辆**：拖动车辆，或在右侧输入坐标、调整车头角度和来车方向。
3. **描述已经发生的动作**：在“已行驶路线”选择直行、转弯、变道或汇入，拖动虚线起点调整来源位置。
4. **标注后续计划**：在“后续动作”选择动作，拖动圆点调整终点、方块调整曲线。直行终点拖向旁边时，会自动切换为变道。
5. **补充现场信息**：标记碰撞点，点选车身受损部位，填写说明、地点和时间。
6. **设置红绿灯**：点击画布上的灯，或从左侧对象列表选择，在右侧调整灯色和朝向。未知灯色不会被假定为红灯或绿灯。
7. **检查演示**：播放已行驶、后续动作或完整演示，检查路线和方向。
8. **导出**：编辑顶部标题，选择格式、比例和清晰度后下载。

点击画布上的道路、车辆或红绿灯，也可以从左侧对象列表切换选中对象。手机端工具面板按需展开，属性区位于画布下方。

### 路线与方向

- **虚线**：到达当前编辑位置之前，已经行驶的路线。
- **实线**：尚未发生的后续计划。
- 左转、右转及左右变道按驾驶员视角判断。
- 匝道侧和进入 / 离开段按所选道路行驶方向判断。
- 变道结束后保持原车头方向；汇入可以设置进入主路后的朝向。
- 红绿灯按来车所在侧配置；小箭头表示标识朝向，文字始终水平显示。

### 演示模式

| 模式 | 内容 | 基础时长 |
| --- | --- | --- |
| 已行驶 | 从路线起点到达当前编辑位置 | 4 秒 |
| 后续动作 | 从当前编辑位置沿计划路线运动 | 4 秒 |
| 完整演示 | 先播放已行驶路线，再衔接后续动作 | 8 秒 |

未设置后续动作的车辆在计划阶段保持原位。演示结束后自动恢复原场景并进入编辑，不将计划改写为已发生事实。演示仅用于表达过程，不还原真实车速或碰撞物理过程。

## 图片和 GIF 导出

### 比例

| 预设 | PNG / JPG 标准尺寸 |
| --- | --- |
| 原图 | 宽 1760 px，高度随标题和说明调整 |
| 小红书 · 3:4 | 1080 × 1440 px |
| 抖音竖屏 · 9:16 | 1080 × 1920 px |
| 方形 · 1:1 | 1080 × 1080 px |
| 横图 · 4:3 | 1440 × 1080 px |
| 宽屏 · 16:9 | 1920 × 1080 px |

PNG / JPG 可选择两倍高清尺寸。小红书和抖音预设使用独立竖版排版，放大标题和正文；长标题、说明会自动换行并调整布局，画布保持等比缩放。

### 格式

- **PNG**：保留清晰线条和文字。
- **JPG**：提供另一种静态图片格式。
- **GIF**：导出已行驶、后续动作或完整演示，循环播放；标准长边最多 960 px，高清长边最多 1440 px，比例不变。终点及完整演示中间阶段会短暂停留，便于阅读。

GIF 在浏览器本地逐帧渲染，由 Web Worker 编码。生成时显示进度，支持取消，无需上传场景到服务器。

导出自动省略未设置的后续动作、空白现场说明及其标题、未注明灯色的红绿灯。已填写的说明、受损部位和已知信号状态正常保留。PNG、JPG、GIF 共用这套规则。

顶部标题最多 60 字，会同步显示在导出图片和文件名中；留空时使用“事故示意图”。静态图片使用当前编辑位置，GIF 根据选定模式演示路线。

## 草稿与快捷键

草稿通过浏览器 `localStorage` 自动保存，键为 `crashpad:draft:v1`，兼容旧版草稿。当前仅保存一个草稿，不提供账号登录或跨设备同步；清除浏览器数据会删除草稿。回放进度、播放速度及画布缩放不写入草稿。

| 操作 | 快捷键 / 方式 |
| --- | --- |
| 微移车辆或碰撞点 | 选中后按方向键 |
| 加速微移 | `Shift` + 方向键 |
| 撤销 | `Ctrl / Command` + `Z` |
| 重做 | `Ctrl / Command` + `Shift` + `Z` |
| 重置场景 | 画布工具栏“重置”，可撤销恢复 |

当前支持两辆车，不包含照片上传、多车场景或责任判定。所有图示均依据绘制者描述生成，位置与距离为示意，不代表事故责任认定。

## 验证与构建

```sh
npm run check
npm test
npx playwright install chromium
npm run test:browser
npm run build
```

浏览器测试覆盖桌面和手机模拟环境，以及实际 PNG、JPG、GIF 下载。截图和下载样本输出到被 Git 忽略的 `test-results/`。

已有本项目开发服务时，复用该实例运行测试：

```sh
CRASH_PAD_REUSE_SERVER=1 npm run test:browser
```

使用本机 Chrome 的示例：

```sh
CRASH_PAD_REUSE_SERVER=1 \
CRASH_PAD_BROWSER='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' \
npm run test:browser
```

构建产物位于 `dist/`，可部署到静态托管服务。要在本地预览构建产物，请先停止占用 `5173` 的开发服务，再运行：

```sh
npm run preview
```

自动化测试使用浏览器设备模拟；真实 iPhone、Android 和内置浏览器的文件保存体验仍需实机验证。

## 技术结构

```text
src/
├── App.jsx                 # 工作台与对象选择
├── components/             # 道路、车辆、信号灯属性、画布与导出面板
├── hooks/useEditor.js      # 草稿、历史和分组编辑
├── hooks/useReplay.js      # 演示时间轴与播放状态
├── model.js                # 场景校验、路线几何和历史模型
├── roads.js                # 参数化道路模板
├── scene.js                # 编辑、预览和导出共用的 SVG 场景
├── socialExport.js         # 小红书 / 抖音竖版排版
├── export.js               # 图片比例适配与 PNG / JPG 下载
├── gifExport.js            # GIF 逐帧渲染、进度与取消
├── gif.worker.js           # GIF 编码 Worker
└── style.css               # 工作台与移动端样式
```

主要依赖：React、Vite、gifenc；自动化测试使用 Node.js Test Runner 和 Playwright。
