# CrashPad 工作台升级执行计划

状态：已完成实现与集成，验收记录见 [工作台升级验证](workbench-upgrade-validation.md)。基线：`dec8ce1` / `feat/editor-sharing`。三个 agent 并行负责编辑状态、共享设计和画布呈现，主 agent 完成页面集成与浏览器回归。

## 目标与边界

以 minimalist-design 为设计原则，让现场还原和车流实验室在导航、设置、画布反馈上形成一致的专业工具体验。保留纯前端、现有模拟规则、导出能力及草稿兼容性。视觉方向为浅色操作面板、石墨灰柏油、低饱和草地和语义化蓝色。

本次不加入服务端、MCP、3D、深色主题、新交通规则或新的状态管理依赖。不合并两个业务模型。不更换存储键或迁移草稿。旧线性入口维持兼容，不作为第三套界面重做。

## 已确认事实

- NetworkApp 的 edit() 对所有改动记录历史并重置模拟；名字逐字输入、比例滑块多次触发，需区分提交事务和修改影响。
- 节点拖动已有本地预览和 pointerup 单次提交，无需重复建设。
- 数字字段直接 Number('') 会得到 0；原生 min/max 不代替业务提交校验。
- 实验身份包含 name，改名可能导致历史跟车结果失去当前实验匹配。
- 现场还原已有文本 flush 和拖动提交机制，复用交互契约，不强行合并编辑器。
- NetworkCanvas 已抵消部分标签/车辆缩放，全景拥挤源于屏幕尺寸固定而道路间距缩小；单纯调字号或按 zoom 百分比分级不够。
- 线性路网存在横断面放大，分级应依据投影车道宽度和设施间距。
- NetworkApp 当前仍有属性页底部“快速开始”，与顶部场景入口有重复；整场景替换和添加路段仍须清楚区分。
- Worker 已有 taskId、实例校验和页面隐藏暂停，保留这些保护。

## 协作与文件所有权

最多主 agent + 3 个 worker。共享工作区内所有 worker 必须知道其他人在同时工作，不得回退他人的修改。

| 负责人 | 独占范围 | 禁止直接修改 |
| --- | --- | --- |
| 主 agent / 集成人 | App.jsx、NetworkApp.jsx、main.jsx、入口接线、集成测试与计划 | 不替 worker 并行改其独占文件 |
| Worker A：编辑状态 | 新 network/useNetworkEditor.js、editHistory.js、实验身份辅助函数及对应测试；约定后调整 useSimulation.js | 引擎、几何、页面入口 |
| Worker B：设计基础 | 新 components/workbench/*、tokens/共享样式；style.css、traffic.css、network.css 的样式收敛 | 模拟逻辑、画布几何、页面入口 |
| Worker C：画布呈现 | NetworkCanvas.jsx、RoadDetails.jsx、presentation.js、新纯展示策略及测试 | model.js、engine.js、layout.js、ramps.js、公共 CSS |

同一个文件同一时间只有一个 owner。页面拆出的 panels 由主 agent 创建后才能转交已空闲 worker。布局所需 CSS 通过 Worker B 集成，禁止另一个 worker 同时追加覆盖规则。scene.js/roads.js 影响导出，最后专门处理并验证，不顺手改几何。

## 阶段 0：锁定接口与基线

主 agent 完成：

1. 确认分支、工作树和已有 5173 预览服务；只复用，不启动重复实例。
2. 保存两个模块桌面基线与城市路网全景/路口细节证据，测试使用独立浏览器上下文，避免覆盖用户草稿。
3. 固定共享控件契约：Header(activeModule, actions, saveStatus)、InspectorFrame(title, open, onOpenChange)、SegmentedControl(value, options, onChange)、ZoomControls(value, onChange, onFit, onFocus)。控件不读取业务存储。
4. 编辑提交契约：commit(mutator, {impact})，impact 默认 simulation；仅明确白名单如 name 可为 presentation。位置、旋转、长度参与几何，仍是 simulation。
5. 保存历史时包含修改影响，undo/redo 执行相同分类。实验身份仅剔除白名单展示字段。

出口：每个 worker 清楚接口、文件 owner、验证责任；不引入全新依赖。

## 阶段 1：三条任务线并行

### A：可靠的编辑提交

- 提取路网编辑历史与提交 hook，保留当前存储数据结构。
- 字段维护本地 draft，Enter/blur 提交，Escape 恢复；输入过程中空值/越界不进入 config。
- 滑块持续显示预览值，结束操作只产生一次历史；覆盖 pointercancel、键盘调整和焦点离开。
- 展示修改不打断运行；影响模拟的修改明确重置并反馈重新运行。
- 正确区分当前文档与运行配置快照，防止旧 Worker 结果映射到新几何。
- 保留过期消息拒绝、暂停和卸载清理。

验收：一次名称/比例修改只需一次撤销；改名时模拟继续；车道/流量变化使旧运行失效；undo/redo 分类一致；改名不改变实验身份。

### B：工作台设计基础

- 从已有蓝色与灰色收敛语义 token，统一字号、间距、圆角、边框和焦点状态。
- 常用控件以 13px、辅助文字以 12px 为基准；通过分组和间距保持密度。
- 提供 Header、HistoryControls、InspectorFrame、SegmentedControl、PlaybackFrame、ZoomControls、Feedback。
- 统一图标尺度、数字对齐、输入单位、禁用与错误表现。
- 提供桌面侧栏和窄屏可收起面板能力；保存失败不能仅靠颜色。
- 避免给每组字段增加卡片、边框与说明横幅。

验收：键盘焦点可见、必要控件有名称、正文与控件达到目标对比度；短选项平铺；百分比支持滑块与输入。

### C：清晰的画布呈现

- 提取纯展示分级策略，输入实际投影空间、缩放和选中状态。
- 全景重点展示路网和关键设施；编辑尺度显示车道与端口；近景显示车辆/信号细节。
- 标签正向阅读，减少重复车道编号；选中对象保留必要信息；避免重要错误因分级被隐藏。
- 优化信号、车辆、标签之间的遮挡，使用屏幕空间包围盒进行必要避让。
- 保留连续柏油与草地，降低纹理干扰；选中态、预览态和错误态语义清楚。
- 不改变物理长度、连接路径、碰撞/让行或速度规则。

验收：城市多路口、收费站、匝道与线性路网在全景和近景均可读；同样配置和种子下模拟结果不受视觉变更影响。

## 阶段 2：主 agent 顺序集成

1. 两模块接入共享导航、历史、缩放呈现和播放壳。各自缩放适配器独立；现场还原保留时间轴，实验室保留实时演进，不能提供无意义的模拟 seek。
2. 从 NetworkApp 拆出对象属性、车流、我的路线、对照、仪表盘。分离 selection、inspectorScope、flowEntryId，避免全局入口选择污染画布选中状态。
3. 场景替换入口集中到顶部，添加路段留左侧；原底部快速开始移出对象属性区。保留旧实验导入入口。
4. 对象属性跟随选择，点击对象不主动移动相机；坐标等低频参数渐进展开。
5. 接入编辑事务与有效性反馈，确认改名、播放、撤销及相机不会相互重置。
6. 仪表盘未运行时摘要显示；运行期间保留用户展开选择；主区详情为紧凑列表加有刻度和时间范围的趋势图。
7. 窄屏属性面板内滚动，主画布与播放入口保持可达；菜单与面板关闭后焦点回到触发点。
8. 最后适配现场还原与导出样式，保证导出不混入编辑辅助标记；PNG/JPG/GIF 能力保持。

出口：现场还原完成“选路—摆车—调整轨迹—回放—导出”；实验室完成“载入—连接/调参—运行—观察—对照”，无重复入口和状态歧义。

## 阶段 3：统一验收与修正

- 状态测试：提交合并、取消、undo/redo、字段边界、展示改动不重置、参数改动使旧运行失效、刷新恢复、A/B 配置快照。
- 画布测试：全景/定位、连接预览、诊断定位、Delete/Backspace、相机手动接管、标签分级。
- 业务回归：现有匝道、收费站、信号、城市/高速预设测试；引擎不变但需保护集成调用。
- 导出回归：现有比例、格式、清晰度、取消与焦点恢复，隐藏辅助标记。
- 视觉：1440×900、1280×720、390×844，另查 320px 重排、200% 页面缩放、键盘与 reduced-motion；记录全景、路口、面板和导出预览截图。
- 浏览器测试集中由主 agent 运行，workers=1；各 worker 可运行互不冲突的纯单元测试。
- 静态：npm run check 是语法检查，不称为 lint 或 TypeScript；新增 JS 检查纳入脚本；集成结束统一运行 check、build、相关单元及浏览器套件。
- 最多两轮审美微调；功能和可访问性阻塞必须修复，不为赶进度忽略。

## 交付与停止条件

交付工作代码、验证记录、前后截图、准确列出的未覆盖项；所有计划内关键验收完成才算本轮升级完成。每阶段可独立回退，避免把行为变化和引擎重写混在一起。

本计划不包含自动提交、推送、PR 或部署；这些作为后续明确交付边界。现有预览服务继续复用。实施中如发现必须迁移持久化数据或改引擎规则，先说明新的范围与风险。

## 实施说明

共享层最终保留 Header、HistoryControls、SegmentedControl、PlaybackFrame、ZoomControls。属性面板保留各模块内容结构，通过同一设计变量和移动端展开契约统一，未保留没有实际复用价值的 InspectorFrame/Feedback 包装。模拟引擎及存储格式未更改。
